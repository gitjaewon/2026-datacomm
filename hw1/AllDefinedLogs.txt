====================================================================
AllDefinedLogs.txt
프로그램에서 정의한 모든 로그 메시지(EVENT) 명세 및 설명
====================================================================

공통 로그 형식:
  [clock] NODE | EVENT | STATUS | message

- clock  : VirtualClock 누적 값(초 단위, 실제 시간이 아님)
- NODE   : MASTER / WORKER1 / WORKER2 / WORKER3 / WORKER4
- EVENT  : 아래에 정리된 자유 형식 이벤트 이름
- STATUS : INFO / SUCCESS / FAIL / WARN 중 하나

※ 노드마다 시계를 따로 굴리므로, 같은 사건을 두 노드가 찍은 시각의 차이는
  통신 지연 1초와 일치하지 않는다 (Readme 8장 참고)
※ 한 노드 안에서 여러 Thread가 같은 파일에 쓰므로, 먼저 읽은 시각이 나중에
  쓰이는 경우에는 직전 줄의 시각으로 올려 찍는다. 그래서 한 파일 안의
  시각은 위에서 아래로 항상 같거나 커진다

--------------------------------------------------------------------
[Master.txt] Master 노드가 사용하는 EVENT
--------------------------------------------------------------------

INIT (INFO, SUCCESS)
  - System Clock 시작, 5,000개 KV 쌍 생성 시작/완료 시 기록
  - 4개 Worker 전부 접속 완료 후 작업 분배 시작 시에도 기록(INFO)

CONNECT (SUCCESS)
  - Worker가 접속 직후 REGISTER 메시지로 자기 workerId를 알려오면,
    그 workerId로 정상 등록됐음을 기록
    (예: "Worker1 connected. Ready Queue initialized (0/10).")

DISTRIB (INFO, WARN, SUCCESS)
  - INFO    : 특정 Worker에게 신규 KV 작업을 분배할 때마다 기록
              (예: "Dispatching KV[0002] (Key=a3f7) -> Worker2")
  - INFO    : 진행률 요약(500개 단위)과 각 Worker의 현재 큐 크기 스냅샷
              (예: "Progress: 500 / 5000 KV pairs stored (10.0%)")
  - WARN    : Worker가 큐 크기 10/10을 보고해왔을 때 기록 (그 Worker로의
              분배 일시 중단). Master는 이 보고값에 아직 도착하지 않은
              작업 수까지 더해서 판단하므로, 이 로그가 없어도 추적값이
              10이면 그 Worker에게는 보내지 않는다
  - WARN    : Worker 큐가 가득 차서 거절된 작업을 다시 큐에 넣을 때 기록.
              장애가 아니므로 재할당 번호와 별도로 번호(#n)를 매김
              (예: "KV[0004] (Key=a3f7) rejected by Worker1 (queue overflow). Requeued (#3).")
  - SUCCESS : 실패한 작업을 최우선 큐에서 꺼내 다른 Worker에게 재할당할 때
              기록. 직전에 실패시킨 Worker는 후보에서 제외
              (예: "KV[0002] (Key=a3f7) reassigned to Worker3 (excluded Worker2).")

RESULT (SUCCESS, FAIL)
  - Worker로부터 작업 처리 결과(RESULT 메시지)를 받을 때마다 기록
  - SUCCESS : KV 저장 완료
  - FAIL    : 20% 규칙으로 처리에 실패한 경우에만 기록. 최우선 큐
              (Priority Queue)에 재등록하며 재할당 번호(#n)를 함께 남김
              (큐 초과 거절은 여기가 아니라 DISTRIB WARN으로 기록)

DISCONNECT (WARN)
  - Worker와의 소켓 연결이 끊어졌을 때 기록 (정상 종료 시 SHUTDOWN
    이후에도 소켓이 닫히므로 이 로그가 함께 남음)

STAT (INFO, WARN)
  - INFO : 전체 처리 완료 후 최종 통계 기록
           (총 처리 건수, 총 SUCCESS/FAIL, 장애 재할당 횟수, 재할당 분배 수,
            큐 초과 거절 수, P2P 이전 송신 횟수(회), P2P 이전 작업 수(건),
            총 수행시간, 그리고 Worker별 통계 한 줄씩)
  - WARN : 종료 시점까지 특정 Worker의 STATS 보고를 못 받은 경우
  - Worker별 줄의 received는 큐 초과 거절도 포함한 값이라, 실제 큐에
    들어간 수를 (accepted=N)으로 함께 적는다

KVSTORE (INFO)
  - 전체 처리 완료 시 KV 저장소 전체(5,000쌍)를 key 정렬하여
    한 줄씩 덤프

TERMINATE (SUCCESS)
  - 모든 Worker에 SHUTDOWN 전송 및 최종 로그 기록 후, Graceful
    Termination 완료 시 기록

--------------------------------------------------------------------
[WorkerN.txt] Worker 노드가 사용하는 EVENT
--------------------------------------------------------------------

INIT (INFO)
  - Worker 스레드 시작 및 Master 접속 시도 시작 시 기록

CONNECT (SUCCESS)
  - Master 접속(TCP 소켓 연결 + REGISTER 전송) 성공 시 기록

RECV (INFO, FAIL)
  - INFO : Master로부터 TASK 메시지(작업)를 수신했을 때 기록
           일반 작업 : "Received task: KV[0002] (Key=a3f7) (Value=83)"
           재할당 작업: "Received PRIORITY task (reassigned): KV[0002] (Key=a3f7) (Value=83)"
  - FAIL : 큐가 이미 가득 차서(10/10) 받은 작업을 즉시 거절했을 때 기록
           (예: "KV[0002] (Key=a3f7) rejected - queue overflow (10/10). Master notified.")

PROC (INFO, SUCCESS, FAIL)
  - INFO    : 작업 처리를 시작할 때(예상 처리 시간과 함께) 기록.
              재할당 작업이면 "Processing retry KV[...] (priority queue)"
  - SUCCESS : 80% 확률로 처리 성공, KV 저장 완료.
              재할당 작업이면 "stored on retry"
  - FAIL    : 20% 확률로 처리 실패, Master에 FAIL 통지
              (재할당 작업에도 같은 80/20 규칙 적용)

QUEUE (WARN)
  - Ready Queue가 70%(7/10)를 초과한 상태에서 작업이 들고날 때마다
    (상태 전이 1회가 아니라 매번) 기록
  - 큐가 이미 가득 찬(10/10) 상태에서 새 TASK가 도착해 즉시
    거부(overflow)할 때도 이 EVENT로 기록 (RECV FAIL과 함께 남음)
  - P2P로 받아서 넘은 경우는 메시지 끝에 "after P2P receive."가 붙고,
    원인이 되는 LB 줄 뒤에 남긴다 (같은 시각이라 순서를 맞춤)

LB (SUCCESS, WARN)
  - P2P 부하 분산(Load Balancing) 관련 이벤트
  - SUCCESS : 내 작업을 다른 Worker에게 이전 성공, 또는 다른
              Worker로부터 작업을 이전받았을 때. 상대 Worker와 이전된
              작업의 key 목록을 함께 기록
              (예: "2 tasks transferred via P2P to Worker3: KV[0002] (Key=a3f7), KV[0012] (Key=0b12). Queue: 9/10 -> 7/10")
              (예: "Received 2 tasks via P2P from Worker1: KV[0002] (Key=a3f7), KV[0012] (Key=0b12). Queue: 5/10")
              1건 이상 실제로 옮겨진 경우에만 남긴다. 보낸 쪽 줄은
              ACK를 받은 시각이 아니라 전송한 시각으로 찍는다
              (ACK를 기다리는 동안 내 파일에 더 늦은 시각의 줄이 먼저
               쓰였다면 위 규칙대로 그 시각으로 올려 찍힌다)
  - WARN    : peer가 이전 요청을 다 받아주지 못해(레이스 컨디션)
              일부 작업이 내 큐로 롤백됐을 때. 롤백된 key 목록을 함께 기록

STAT (INFO)
  - Worker 종료 직전, 자신의 최종 통계를 기록
    (수신 작업 수, SUCCESS(처리량), FAIL(20% 규칙), 재할당 작업 수신 수,
     큐 초과 거절 수, 평균 대기시간, P2P 이전 송신 횟수(회),
     P2P 이전 작업 수(송신/수신), 총 수행시간)
  - Total tasks received는 큐 초과 거절도 포함한 값이라, 실제 큐에 들어간
    건수는 같은 줄의 (accepted N)을 본다
  - P2P send events는 내가 이전을 건 횟수만 센다 (받은 쪽은 미포함)

TERMINATE (SUCCESS)
  - SHUTDOWN 메시지 수신 후 Master 연결을 정상 종료할 때 기록
